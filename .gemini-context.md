# Project Mandates: Equinox Loader

Ce document définit les règles architecturales et les standards de développement pour le projet Equinox Loader. Ces instructions sont prioritaires.

## 1. Vue d'Ensemble
Ce projet est un chargeur de framework OSGi (Eclipse Equinox) personnalisé permettant l'initialisation, la gestion de cycle de vie des bundles et le management via RMI/JMX.

## 2. Architecture & Modules
L'agent doit respecter la séparation stricte des modules Maven :
- **tc-osgi-bundle-utils-interfaces** : Contrats de service et API communes. **Aucune implémentation lourde ici.**
- **tc-osgi-bundle-utils** : Implémentations socles (Logging, Configuration, RMI). C'est la dépendance centrale.
- **tc-osgi-bundle-manager** : Gestionnaire de bundles JMX et interfaçage avec les dépôts distants.
- **tc-osgi-equinox-loader** : Point d'entrée principal (`EquinoxLoaderMain`). Gère le bootstrapping d'Equinox.

## 3. Standards d'Ingénierie
- **Logging** : Utiliser exclusivement `org.tc.osgi.bundle.utils.logger.LoggerGestionnary.getInstance(MyClass.class)`.
- **Patterns Mandatoires** :
    - **Command Pattern** : Obligatoire pour toute opération sur le cycle de vie des bundles (ex: `LoadDefaultBundleCmd`).
    - **Singleton** : Utilisé pour les gestionnaires de configuration (ex: `EquinoxPropertyFile.getInstance()`).
- **Configuration** : Les paramètres doivent être déclarés dans les fichiers `.properties` de `src/main/resources`.
- **Services OSGi** : Privilégier l'exposition des fonctionnalités via des services OSGi déclarés dans les `Activator`.

## 4. Build & Déploiement
- **Target OS** : Linux (Debian).
- **Packaging** : Maven avec le plugin `jdeb` pour les paquets `.deb`.
- **Docker** : Utilisation du `docker-maven-plugin`.
- **Dépôt** : Repository Nexus privé : `http://collonvillethomas.freeboxos.fr:8888/nexus`.
- **Arborescence cible** : Les bundles sont installés dans `/opt/equinox-loader/bundles`.

## 5. Validation & Tests
- **Frameworks** : JUnit et Mockito.
- **Contraintes** : Toute modification doit tenir compte des contraintes de classloading OSGi et de la visibilité des packages exportés dans les `pom.xml` (via `maven-bundle-plugin`).
